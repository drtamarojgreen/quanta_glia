# Cross-Platform Console Terminal Application Enhancement Plan

This section expands the enhancement roadmap for building a cross-platform C++ console terminal application for Glia under a modular package system rooted in `src/`. The plan keeps the application free of additional libraries and frameworks: every proposed module should rely on the C++ standard library, the C++ runtime, and small in-repository code only. The design goal is to preserve the Glia capabilities described across the project—harvesting, pruning, semantic annotation, knowledge curation, trigger-based behavior, auditability, configuration, reporting, workspace orchestration, and resilient operation—while making those capabilities available through a portable terminal interface.

## Development Principles

- **Standard C++ only:** Prefer C++17 or newer standard-library facilities such as `<filesystem>`, `<thread>`, `<chrono>`, `<regex>`, `<optional>`, `<variant>`, `<string_view>`, `<sstream>`, and `<iomanip>` instead of third-party packages.
- **Terminal-first interaction:** Provide deterministic command-line workflows that run consistently on Linux, macOS, Windows terminals, SSH sessions, and CI jobs.
- **Modular `src/` packages:** Organize features as small packages under `src/` with clear interfaces, minimal coupling, and testable implementation files.
- **No hidden framework dependency:** Avoid Qt, ncurses, Boost, external JSON/YAML libraries, external CLI parsers, and platform-specific shells for core behavior.
- **Graceful portability:** Isolate unavoidable platform differences behind narrow adapters implemented in the repository.
- **Feature parity:** Carry forward Glia's harvesting, pruning, semantic annotation, knowledge curation, trigger behavior, logging, reporting, configuration, and safety controls.

## Suggested `src/` Package Layout

```text
src/
├── app/                 # process startup, command dispatch, exit-code policy
├── cli/                 # argument parsing, terminal rendering, help, prompts
├── config/              # standard-library config readers and validators
├── core/                # domain entities, result types, errors, clocks, IDs
├── harvest/             # repository/path collection and target file extraction
├── prune/               # scoring, decisions, archive/delete simulation
├── annotate/            # semantic tags, topic extraction, metadata records
├── curate/              # knowledge bundle grouping and contradiction flags
├── trigger/             # repeated-pattern and knowledge-gap detection
├── storage/             # filesystem knowledge base, repo cache, ledgers
├── report/              # CSV, text tables, summaries, trend snapshots
├── audit/               # append-only decision logs and rationale trails
├── safety/              # dry-run, sandbox, human-review, policy gates
├── platform/            # OS, process, path, terminal, and environment adapters
├── util/                # strings, parsing, checksum, timestamps, small helpers
└── tests/               # standard-library executable tests and fixtures
```

## 200 Enhancement Components

### App Shell and Command Model

4. **Exit-code taxonomy:** Define stable exit codes for success, usage error, configuration error, filesystem error, policy denial, partial success, and internal failure.
5. **Application context object:** Pass a lightweight context containing paths, config, terminal mode, clock, and audit writer through packages.
6. **Command lifecycle hooks:** Standardize pre-run validation, execution, post-run reporting, and cleanup for every terminal command.
7. **Feature flag registry:** Add compile-time and runtime feature switches for experimental Glia capabilities while keeping the binary dependency-free.
8. **Self-description command:** Add `glia about` to print version, build profile, enabled modules, standard level, and platform details.
9. **Capability discovery:** Add `glia capabilities` to list available Glia functions and whether each is enabled, planned, dry-run-only, or human-review-only.
10. **Workspace bootstrap command:** Add `glia init` to create knowledge base, repo cache, archive, report, and audit directories using `std::filesystem`.
11. **Consistent command result type:** Use a common result object with status, user message, detail message, and optional remediation hints.
12. **Non-interactive mode:** Add `--no-input` for CI and automation where all confirmation prompts must fail closed unless pre-approved.
13. **Interactive confirmation mode:** Add standard input prompts for human-in-the-loop pruning, archive, merge, and overwrite decisions.
14. **Command dry-run propagation:** Ensure `--dry-run` flows through every package so simulated actions never mutate files.

16. **Composable command pipelines:** Let commands emit manifest files that later commands can consume, such as harvest manifests feeding prune scoring.
